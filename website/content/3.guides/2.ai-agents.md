artisan works well as a tool for AI coding agents: the commands are short, the output is compact, and the notes
workspace gives an agent a place to remember what it did between sessions.

## Output an agent can read

When the output goes to a pipe, a file or an AI coding agent, tables print as compact tab-separated rows
(`== Title ==`, then a header line and the rows): about half the size, with no truncation, and ready for
`cut -f2` / `awk -F'\t'`. Force it either way with `--plain` / `--table`, or set `ARTISAN_PLAIN=1` / `ARTISAN_PLAIN=0`.

```text
== Missing translations per module (+n = extra keys not in values/) ==
Module	keys	ar	de	ur
:app	412	0	2	1 +3
:core	57	0	0	0
```

## The `:ai` workspace

```sh
artisan make:ai [x.y] [stage]
```

Adds an `:ai` Gradle module that holds the AI-agent workspace in `ai/src/main/java/ai/`, visible in Android Studio
and never shipped:

![The :ai module in Android Studio: assets, event/event.md, plan, workflow and README.md](/img/ai-module.png)

| Path | What |
|---|---|
| `README.md` | Rules for agents, keeping `:ai` out of production, tracking conventions |
| `workflow/v_x_y_alpha/` | `overview.md` + `phase_1.md`: versions → phases → changes and bugs |
| `assets/` | Screenshots and recordings (`app:shot`, `app:record`, `make:bug --shot`) |
| `event/event.md` | Pre-filled with every `firebaseEvent(` name per screen, plus the [naming rules](/commands/code-health#eventmd) |
| `plan/` | Plans (`make:plan <name>`: one `.md` file) and re-apply bundles (`make:bundle`), indexed in `plan/MASTER_OVERVIEW.md` |
| `index.html` + `site/` | The workspace as a site, opened with `artisan ai:site` (below) |
| `app.json` | App name, tagline, areas and feature groups the site shows |
| `requests/`, `reports/` | Feature requests / bug reports and daily work reports, written from the site |
| `workflow/<version>/release.json` | Plain-English release notes for the site's Releases and Coming soon pages |

Details:

- Adds `include(":ai")` to the settings file. The module is a plain `java-library` (plus the Kotlin JVM plugin when
  the version catalog already has it), and no other module may depend on it.
- Default version: `versionName` + `alpha`.
- When adb or `JAVA_HOME` is missing, it finishes by running `setup`.
- The [notes commands](/commands/notes) find it without any config.
- At a terminal it asks four plain questions for the site, each pre-filled from the project: the app name
  (`app_name`), one line about the app, the main colour (a word like `blue`, `red`, `orange`, `dark green`, or a
  hex; the default comes from the Compose theme or `colorPrimary`), and the main parts of the app (feature modules
  plus UI, Ads, Splash, i18n, Core, Other). Scripts and agents get the defaults without prompts.
- Run it again on a project that already has `ai/` and it adds only the site, leaving the notes alone.

## The workspace site

```sh
artisan ai:site [--port 5173] [--no-open]
```

Serves the workspace on `http://127.0.0.1:5173/` (this machine only) and opens the browser. It's one page,
`index.html` with Tailwind and Alpine.js from a CDN: nothing to install, no npm, no build step.

- **Public view**, for testers, managers and users: Home (the app's feature groups), Releases (from each
  `release.json`, or the phase table when there's none), Coming soon (planned changes, open bugs, accepted
  requests), and a Request form for features and bugs, screenshot included.
- **Dev view**: a dashboard (open phases, VERIFY ON DEVICE, ASK DEV, work streak), Workflow (every checklist line
  with filters), Plans with a reader, Analytics events, Assets (orphans flagged), the Requests inbox (change status)
  and Work reports (log time, copy the daily report, export the final one).
- Edit any note and the open page updates within a couple of seconds. Saving from the site only writes plain `.md`
  files in `requests/` and `reports/` (and a `[H:MM]` stamp on a phase heading when a day's report is exported).
- Ctrl/⌘ K searches everything. The brand colour is `window.BRAND` at the top of `index.html`.

## Porting a feature between project copies

`artisan make:bundle <feature> --since <tag>` snapshots what changed into `plan/<feature>/` and lists it in
`plan/MASTER_OVERVIEW.md`, so a shipped feature can be ported into a new copy of the project without re-designing it.
See [Re-apply bundles](/commands/make#re-apply-bundles).

## Suggested agent instructions

Paste into your agent's instructions file (`CLAUDE.md`, `AGENTS.md`, `.cursorrules`):

```md
- This is an Android project with kotlin-artisan. Run `artisan list` to see the commands.
- Track work in ai/src/main/java/ai/ (see its README.md). New plan: `artisan make:plan <name>`.
- New strings: `artisan make:string <key> "text"`. New analytics events: `artisan make:event ...`, then `artisan check:events`.
- Before finishing: `artisan check:strings`, `artisan check:events`, `artisan check:links`.
```
