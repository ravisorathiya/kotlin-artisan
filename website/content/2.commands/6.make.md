notes generators (`make:plan`, `make:bug`, `make:ai`, ...) on [Notes workspace](/commands/notes).

## Screens

```sh
artisan make:screen activity Settings
```

`SettingsActivity.kt` + `res/layout/activity_settings.xml` + the `<activity>` entry in the manifest. ViewBinding when
the module has it on, else `R.layout`. Also `fragment`, `dialog` (DialogFragment), `sheet` (Material bottom sheet).
`--package presentation.settings` (relative to the namespace); without it, it asks with a guess from where the other
screens live.

### Your own templates

```sh
artisan stub:publish
```

Copies the screen templates to `artisan/stubs/` (`activity.kt.stub`, ..., `layout.xml.stub`). Edit them to use your
base classes; `make:screen` uses them from then on.

| Placeholder | Becomes |
|---|---|
| `{{PACKAGE}}` | The screen's package |
| `{{CLASS}}` | `SettingsActivity` |
| `{{LAYOUT}}` | `activity_settings` |
| `{{BINDING}}` | `ActivitySettingsBinding` |
| `{{NAMESPACE}}` | The module's namespace |
| `{{HEIGHT}}` | The layout root's height: `match_parent` for activities and fragments, `wrap_content` for dialogs and sheets |

## Re-apply bundles

```sh
artisan make:bundle <feature> --since v1.7
```

Everything that changed in the app's modules since the tag (committed or not; `:ai` and build output left out)
becomes a re-apply bundle in `plan/<feature>/`:

- `reference/<File>.txt` snapshots
- `apply_bundle.ps1`: dry run by default; `-Apply` adds new files; `-Apply -IncludeModified` also replaces modified
  files after a `.bak_<feature>` backup
- `overview.md` with the new / modified / deleted tables
- a row in `plan/MASTER_OVERVIEW.md`

Copy the folder into the next project zip and run the script. See
[Hand the feature to the next project copy](/guides/a-day-with-artisan#hand-the-feature-to-the-next-project-copy).
